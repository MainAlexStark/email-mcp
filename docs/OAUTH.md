# Вход, ящики и подключения Claude

## Кто есть кто

- **Пользователь** — учётная запись сервиса: почта и пароль от кабинета. Регистрируется сам (`MAIL_REGISTRATION=open`), по приглашению (`invite`) или не регистрируется вовсе (`closed`).
- **Ящик** — почтовый ящик пользователя: адрес, IMAP (и, по желанию, SMTP), логин и пароль приложения. Вход проверяется на живом сервере до сохранения; пароль хранится зашифрованным. У ящика есть `account_id` — короткое имя, которое модель передаёт в инструменты.
- **Подключение** (OAuth-выдача) — доступ одного приложения (Claude на ноутбуке, Claude на телефоне) к **всем** ящикам пользователя или к **одному** выбранному, с отмеченными правами. Отзывается в кабинете поштучно.
- **API-токен** (`emc_…`) — то же самое для скрипта, который не может пройти экран согласия.

## Права

| Право | OAuth-scope | Что открывает |
|---|---|---|
| Чтение | `mail:read` | поиск, письма, вложения, папки. Выдаётся всегда |
| Черновики | `mail:drafts` | `draft_create`, `draft_update`, `draft_delete` |
| Изменение ящика | `mail:write` | флаги, перенос, удаление (по умолчанию — в корзину), папки, `imap_append_message` |
| Отправка | `mail:send` | `smtp_send_message`, `smtp_reply_message`, `smtp_forward_message`, `draft_send` |

Почему четыре права, а не привычные read/write: у почты три разных вида риска. Черновик никуда не уходит — человек увидит его в своей почте. Изменение ящика обратимо не всегда. Отправленное письмо не вернуть вовсе. «Подготовь ответы, я отправлю сам» — это чтение + черновики, и для этого не нужно давать модели право отправлять от вашего имени.

## Все ящики или один

На экране согласия выбирается «Все ящики» (по умолчанию; в том числе подключённые позже) или один конкретный. Подключение к одному ящику не видит остальных вовсе — ни в `list_all_accounts`, ни по `account_id`. Его выбирают для приложений, которым не стоит знать о личной почте.

В отличие от магазинов в ozon-seller-mcp, где подключение всегда к одному магазину, здесь ящик выбирается аргументом `account_id`: люди ведут переписку сразу из нескольких ящиков, и «найди письмо от Боба, где бы оно ни было» — обычная просьба. Перепутать ящик при отправке модель может, поэтому отправка — отдельное право, а в описании отправляющих инструментов прямо требуется предпросмотр с адресом отправителя.

## Как это выглядит

```
Claude                     сервис                          браузер пользователя
  │                          │                                    │
  ├─ запрос без токена ─────►│                                    │
  │◄──── 401 + метаданные ───┤                                    │
  ├─ регистрируется (DCR) ──►│                                    │
  ├─ открывает браузер ──────┼───────────────────────────────────►│
  │                          │◄── не вошёл? → /login → обратно ───┤
  │                          │◄── нет ящика? → подключить ────────┤
  │                          │◄── выбрал ящики и права ───────────┤
  │◄──── код авторизации ────┤                                    │
  ├─ меняет код на токен ───►│   токен = пользователь + ящик(и) + права
  │◄──── токен на 1 час ─────┤                                    │
  ├─ работа с токеном ──────►│ → пароль этого ящика → IMAP/SMTP
```

## Что устроено именно так и почему

**Токены непрозрачные, а не JWT.** Подписанный токен нельзя отозвать до истечения срока. В базе — только SHA-256 токенов.

**Удаление ящика убивает подключения к нему сразу.** Токены к конкретному ящику ссылаются на него с `ON DELETE CASCADE`. Подключения «ко всем ящикам» остаются, но удалённого ящика больше не видят: ящики читаются из базы на каждый запрос.

**Пароли ящиков зашифрованы с привязкой.** AES-256-GCM, мастер-ключ `MAIL_SECRET_KEY` в окружении процесса. Шифротекст привязан к пользователю и логину: переставленный в чужую строку базы, он не расшифруется. В кабинет пароль не возвращается никогда — даже в форму после ошибки.

**Внутренние адреса запрещены.** Адрес IMAP/SMTP вводит пользователь. Без запрета проверка ящика стала бы сканером сети сервиса: `postgres:5432`, `169.254.169.254`, `127.0.0.1:…` — по тексту ошибки видно, открыт ли порт. Проверка стоит на уже разрешённом IP (Control у `net.Dialer`), поэтому DNS, отдающий внутренний адрес, её не обходит. Соединения без TLS запрещены по той же причине, что и в браузере. Свой почтовый сервер в той же сети — `MAIL_ALLOW_PRIVATE_HOSTS=true`.

**Приглашения одноразовые и атомарные.** Код гасится в той же транзакции, что создаёт пользователя: двое с одним кодом не зарегистрируются оба, а неудачная регистрация (адрес занят) код не сжигает. В базе — только хеш кода.

**Остальное — как в стандарте:** ротация refresh, проверка audience, кабинет без JavaScript со строгим CSP, CSRF на каждой форме, одна фраза на «нет такого адреса» и «не тот пароль», ограничение частоты входа и регистрации, открытая регистрация клиентов с чисткой неиспользованных.

## Если не подключается

**Claude не видит сервер.** `401` должен приходить с `WWW-Authenticate`, в котором есть `resource_metadata`:

```bash
curl -si -X POST https://mail-mcp.example.com/mcp -d '{}' | grep -i www-authenticate
```

**После входа снова форма входа.** Cookie не доходит: сервис открыт не по `MAIL_PUBLIC_URL` (другой домен или http вместо https).

**«Ящик этого подключения удалён или недоступен».** Ящик удалили в кабинете — подключите сервер в Claude заново.

**Ящик не подключается.** Почти всегда — пароль приложения. Текст ошибки в кабинете называет, где его взять у вашего провайдера; таблица — в [PROVIDERS.md](PROVIDERS.md).
